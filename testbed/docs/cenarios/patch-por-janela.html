Cenários de sincronização: placar e estatísticas

Como cada tela chega ao estado atual de uma partida, com a deduplicação de subscriptions do Router e cache nas queries. Placar e estatísticas são canais separados, cada um com a sua subscription, versão, snapshot e forma de envio. Clique em um passo para ver o estado dos dois canais depois dele, ou use Reproduzir.

canal placar · subgraph scores

scoreboardUpdates(matchId)

Muda
poucas vezes por partida: gol, início, intervalo, fim
Frame
STATE com o placar inteiro (~150 B), na hora de cada commit e a cada 1 s
Regra
o frame de maior versão vence; nunca há lacuna a recuperar
Relógio
não é enviado: o cliente avança a partir de seconds e updatedAt
canal estatísticas · subgraph stats

statsUpdates(matchId)

Muda
~20 lances/s, rajadas de 200/s
Frame
um a cada 500 ms: DELTA (valores finais do que mudou) ou STATE (estado inteiro), o que for menor; CHECKPOINT a cada 1 s
Regra
aplica DELTA se from ≤ versão local < version; se não, pede um snapshot com versão mínima
Histórico
não existe: a recuperação é sempre um snapshot
query · cache 2 s / 60 s
scoreboard(matchId, minVersion)

"Um placar consistente em alguma versão ≥ minVersion." Com 0, é a chave compartilhada para o render imediato.

query · cache 5 s / 60 s
matchStats(matchId, minVersion)

Mesmo contrato. Com minVersion = v vindo do stream, é uma chave nova que nenhuma resposta antiga satisfaz.

query · cache 1 h
